### Slippery-world, as specified by the user

$N \times N$ grid; position is **input** variables; `l/r/u/d` are **outputs**;
nondeterminism is whether a move advances 1 or 2 cells, determinized by a fresh
**`slip`** input on which the position variables then functionally depend,
together with the `lrud` history.

Defaults taken in the grill (objectable, not yet contradicted):

- **Walls are no-ops** (bumping = stay), not forbidden moves.
- **$\delta$ is total over all 16 `lrud` combinations** via a fixed priority
  (no direction = stay).

Both exist to keep $A_{\text{rest}} = \top$: the moment a wall *forbids* a move
or "exactly one direction" is *required*, that constraint restricts **outputs**,
cannot live in $\Tin$, and lands back in the formula on both sides.

- **Moore check (this is the thing a reimplementation gets wrong first):**
  $\lambda_{in}$ may not observe the current step's outputs
  (the `\cl` note under `\cref{def:indep}`, input-dependencies PRD *I3*). The
  encoding survives because
  position at $t{+}1$ is a function of position$(t)$, `lrud`$(t)$, `slip`$(t)$ —
  all *history* at $t{+}1$.
- **Free realizable/unrealizable pair:** adversarial `slip` makes *reach a
  corner* realizable (walls absorb overshoot) and *reach a centre cell*
  generally not (slip controls arrival parity). Same domain, same $\Tin$; the
  flag moves $\gamma$ only.

### Findings from the grill that change the implementation estimate

1. **The race protocol already exists.** `src/ltlf_ek_bench.cpp:837` (on
   `worktree-presentation-2026-08-12`) builds `(psi_in) -> (phi)` for
   `ltlfsynt` while the methods get `(phi, T_in, T_out)`. Setting
   $\psi_{in} = A_n$ and $\varphi = \gamma_n$ *is* idea 1. **Idea 1 needs new
   families and the certificate — not new race machinery.**
2. **Q3's certificate hardens what already shipped.** Tier T1 currently
   declares $\psi_{in}$ by hand with nothing checking it against $\Tin$
   (PRD B3). The language-equivalence check closes that hole for the existing
   families too.
3. **$\lvert\Tin\rvert \geq \lvert\mathrm{DFA}(A)\rvert$, always** —
   `OutputLabeledTransducer` (`include/ltlf_ek/output_labeled_transducer.hpp:36`)
   has explicit-state $\delta$, which *is* a DFA for $A$. So the EK win can
   never come from a smaller representation. It has exactly two sources, and
   the PRD should name them rather than let them be discovered:
   - **translation cost** — the baseline pays LTLf→DFA (2EXP) on $A$; the EK
     side is handed $\mathrm{DFA}(A)$ and translates only $\gamma_n$;
   - **`cons` pruning during on-the-fly construction** — Method 3.1's 5488×;
     only `OtfMtdfaProduct` gets it.
4. **Corpus ingestion is an adapter, not a parser.** The repo's part-file
   (`include/ltlf_ek/cli.hpp:19`) is a 4-key superset of the `.inputs:` /
   `.outputs:` convention, and a sampled `tlsf-fin` file carries its formula as
   plain LTL syntax in a single `GUARANTEES` block that Spot can parse after the
   TLSF wrapper is stripped (`&&`→`&`, `||`→`|`). **Unverified on the harder
   files** — that is Monday's job.
5. **Turn-order hazard, silent.** `tlsf-fin` declares `SEMANTICS: Finite,Moore`
   and writes outputs under `X[!]`. `include/ltlf_ek/turn_order.hpp` requires
   Mealy BDD ordering and warns that the wrong order "silently yields Moore
   semantics and a WRONG verdict — no crash". Monday must settle this before
   any corpus number is believed.
6. **The user's own prediction, and why it is not a problem.** Arm (a) is
   expected to find few dependencies: nondeterministic domains must be
   determinized before dependencies exist, and output dependencies are rare.
   That is the `slip` move. **A null result in arm (a) is the motivation
   experiment for the paper** — if real specs carry no exploitable dependency,
   external knowledge cannot come from $\varphi$ and must come from outside it,
   which is exactly what the Introduction of `main.tex` already asserts — *"when
   solving PDDL problems, the domain is external knowledge to the goal"* — and
   nobody has measured.

## Standing rules for every unattended run this week

  blocker and stops (`docs/unattended-workflow.md`).
- `ltlfsynt` is invoked by **absolute path** `~/opt/spot-2.15.1/bin/ltlfsynt`;
  the bare name resolves through `PATH` to a 2.14.4.dev install and would
  silently race the wrong version.

  on `mkstemp`.
- Never let raw build output into context; redirect and `tail` on failure.
- Stage explicit paths — never `git add -A` while worktrees exist.
- A verdict disagreement anywhere is a **theory finding** (Stop-list 4), not a
  benchmark bug.

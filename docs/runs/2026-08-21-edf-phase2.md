## 3. Findings

### F1 — `slippery-onehot` at $n = 4$ dies of `std::bad_alloc`, and the cause is **ours, not the family's**

The T1 sweep tried $n = 4$ as a fast-conditional extra. `slippery-binary` at
$n = 4$ certifies in ~1.6 s per goal; `slippery-onehot` at $n = 4$ throws
`std::bad_alloc` and was dropped from the test.

**This section originally said the allocation failure was `ltlf_to_dfa`
building the 32-AP $A_N$ — that was wrong**, and the generic review measured it:
`ltlf_to_dfa(psi_in)` for that exact case builds in **0.64 s with 258 states**.
The real cause is in the API this phase wrote — `produced_trace_equivalence.cpp`
enumerates the letter alphabet **eagerly**, as a `vector<bdd>` of $2^{\lvert
AP\rvert}$ cubes. One-hot at $n = 4$ carries 37 APs, i.e. $\approx 1.4\times
10^{11}$ entries. See §4, generic finding 2.

The consequence for the evening: **capping the one-hot arm at $n = 3$ would be
treating our own alphabet-enumeration choice as a property of the family.** The
Stop-list 8 reading ("one-hot dying at large $n$ is a data point") still holds
for the *methods*, as Phase 1 measured — but it does **not** explain this
particular death, and Phase 4's expectation should not be set from it until the
enumeration is fixed.

### F2 — the new oracles add ~220 s to every `ctest` run, for the same reason

`slippery-onehot` at $n = 3$ costs ~110 s per goal inside the T1 sweep. The
coverage is what the PRD asks for at $n = 2,3$, so it was kept rather than
weakened. But the review traced the cost to the same eager enumeration
($k = 21 \Rightarrow 2^{21}$ cubes built, then rescanned per product state
through `goal_delta`'s linear edge scan), so this is **not** an inherent price
of the coverage — it is a fixable implementation choice. Whether to fix it or to
put the slow cells behind an opt-in (the `LTLF_EK_SOAK` precedent) is a user
call; the honest reading is that the fix is the better trade and the opt-in
would be hiding it.

### 4a. Generic (`/code-review 13`) — one soundness bug, fixed; two findings left open

**Fixed (`6cd8d9b`) — the certificate could return a false green.**
`src/produced_trace_equivalence.cpp` pre-seeded `visited` with the initial
product pair, so **any non-empty word that returned the walk to that pair was
pruned before its finality was tested** — and that pair always differs
(`emits_dfa`'s initial state is final by construction, `ltlf_to_dfa`'s is not).
Repro, confirmed against independent reference walkers: `tau` = trivial
transducer over one AP ($L(\tau) = \Sigma^+$) against $\psi = F(i)$ reported
**equivalent**, though `[!i]` is in $L(\tau)$ and not in $L(\psi)$. It bites any
$\psi$ whose DFA initial state is re-reachable, i.e. any assumption without an
initial-state pinning conjunct — and **T6 cannot catch it**, because both
mutants keep the `(!bx0)` conjunct that makes $\psi$'s initial state unreachable.

That is a false green in the one API whose entire job is soundness, so it was
fixed rather than recorded: the walk now starts from a virtual pre-initial node
(parents are `optional<Key>`), the empty word is still excluded from the verdict
and reported only in `empty_word_agrees`, and the reviewer's repro is now a
regression test. **The PRD's pinned behaviour #2 caused it** — "some reachable
state pair *other than the initial pair*" — and has been corrected to say what
was meant: the empty *word* is excluded, not the initial *pair*.

**Every T1 cell and both T6 mutants stayed green under the corrected walk**, so
the retrofit's result in §2 survives the fix — which is the only reason it is
still quotable.

**Left open — at the review-round cap (2 of 2), deliberately not fixed today:**

1. `src/produced_trace_equivalence.cpp:57` — the eager $2^{\lvert AP\rvert}$
   letter vector behind F1 and F2 above. Also: `std::size_t{1} << k` is **UB for
   $k \ge 64$** and is unguarded. The fix is to enumerate the DFAs' actual edge
   cubes instead of the full minterm space; that is a real design change to code
   written today and did not fit inside the cap.
2. `src/produced_trace_equivalence.cpp:37` — the `tau_dfa->ap()` harvesting loop
   is **dead code** (`emits_dfa` never calls `register_ap`), so the documented
   safety net only ever covers the $\psi$ side. A `Transducer` guard mentioning
   an AP outside `vars.universe()` then yields non-full cubes, and `goal_delta`'s
   first-intersecting-edge match silently takes the wrong edge — reachable
   through the public API, which the repo's own tests drive with hand-built
   `twa_graph`s.

**Clean in the generic pass:** the slippery-world generator itself. The reviewer
checked `slippery_assumption`'s per-axis decomposition against
`slippery_transducer_hoa` case by case (movers vs non-movers, slip, wall
clamping, the $14N+1$ count) and found no mismatch; the five-class guards are
pairwise disjoint and exhaustive, so $\delta$ is total by construction as
claimed. `build_nk_case`'s demote-then-build ordering and dict handling are
correct.

### 4b. Domain (`/code-reviewer`) + theory (`/theory-reviewer`)

**No `code-bug`.** Two `must-fix`, both documentation,
both applied in `31fb6e8`:

1. T6's deviation (below) was argued in a source comment; it belongs in the

2. The header and the PRD's pinned behaviour #1 said "a missing edge on
   **either** side is an implicit rejecting sink". Only $\tau$'s side gets a

   `doc-bug`, low severity. The **prose** was corrected; the code's behaviour is
   the right one.

**Deferred (`consider`, not acted on, recorded in the PRD):** the PRD's pinned
behaviour #3 says witnesses are enumerated "in `bdd_dict` variable order"; the
implementation orders by `sigma_slices`-then-lexicographic-AP-name. Fully

say the same thing.

**Two deviations from the PRD as written, both recorded, neither silent:**

- **T6 was built on a reduced one-axis "slippery-line" ($N = 2$)** rather than on
  mutants of the family's own $A_N$, because D5's `Keep`/`Inc` vocabulary lands
  in Phase 3. `/code-reviewer` judged this an **acceptable** realization, not a
  hollowing-out: T1 already exercises the real generator on every registered
  family, so T6's job is only to prove the machinery discriminates on
  genuinely satisfiable too-weak / too-strong mutants — which it does, against
  independent reference walkers.
- **Pinned behaviour #5 ("slices come from `sigma_slices`") did not say what the
  slices feed.** The implementation uses them to order the BFS's letter
  enumeration while walking the **full** $I \cup O$ alphabet regardless of
  `role`. Reviewed against Stop-list 1: this is the *non-narrowing* reading —
  restricting the walk to $\Sigma_0 \cup \Sigma_1$ would blind the certificate
  to exactly the `mv`-guard mutant T6(b) is built to catch.
